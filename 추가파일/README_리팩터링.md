## 1. 진단

반응형이 미구현이었던 것이 아니라, **한 축(세로)에만 구현되어 있고 축소 방향으로는
잠겨 있었다.** ResizeObserver, `--frame-h` 실측, `transform:scale` 등 기구는 이미 있었고
문제는 그 설계 전제였다.

### 근본 원인

**① 스케일에 하한 1.0이 박혀 있었다**

```js
const s = Math.max(1, Math.min(w / OFFICE_ROOM_W, h / OFFICE_ROOM_H) || 1);
```

`.office-layer` 는 476×337 좌표계를 scale 로 맞추는데 **확대만 되고 축소는 금지**되어 있었다.
여기에 `.game-container { min-width: 480px }` 가 겹쳐, 폭 480px 미만 기기는 전부 잘렸다.
현재 주력 폰은 360~430 CSS px 이므로 모바일이 사실상 불가였다.

**② 컨테이너 폭이 세로 길이의 함수였다**

```css
width: calc(max(var(--room-min), 95vh - var(--chrome-h)) * var(--room-min-w) / var(--room-min) + 4px);
```

뷰포트 **폭이 계산식에 없다.** 창을 아무리 넓혀도 반응하지 않은 직접 원인.

**③ 세로 UI 합계 738px 가 16:9 화면에서 무대를 압살했다**

헤더+연봉바+사직서바+탭+목록이 `--chrome-h = 738px` 를 먹으니 950px 뷰포트에는 212px만 남는다.
**1열 구조로는 데스크톱에서 무대가 커질 수학적 여지가 없었다.**

| 환경 | 가로 스크롤 | 세로 스크롤 | 무대 배율 | 가로 여백 |
|---|---|---|---|---|
| Galaxy S20 360×800 | **발생 (33% 잘림)** | – | 1.00 | – |
| iPhone SE 375×667 | **발생** | **발생** | 1.00 | – |
| 노트북 1366×660 | – | **발생** | 1.00 | **65% 낭비** |
| FHD 1920×950 | – | – | 1.00 | **75% 낭비** |

부수 문제: `95vh`/`100vh` 사용(모바일 주소창 미대응), 미디어쿼리 2개뿐이고 둘 다 색·테두리만 손댐,
`--frame-h` ↔ 폭 순환참조를 budget 카운터로 억지 수렴시키는 구조.

## 2. 변경 내용

### 2.1 좌표계 (불변 유지)

**배치 좌표계 476×337 은 건드리지 않았다.** 저장된 아이템 좌표(`equippedByRoom`)의 기준이라
바꾸면 기존 세이브가 깨진다. 화면 대응은 전부 `.office-layer` 의 `transform: scale()` 로만 처리한다.

```js
// 하한 제거: 주어진 상자에 476:337 을 '맞춰 넣는다'(contain)
let s = Math.min(w / OFFICE_ROOM_W, h / OFFICE_ROOM_H);
```

드래그 좌표는 원래부터 배율로 정규화(`/s`)하고 있어 축소를 허용해도 수식 변경이 없다.

### 2.2 레이아웃

CSS 는 `<style>` 맨 끝의 **"반응형 레이어"** 블록에서 크기를 결정한다. 앞쪽 규칙은 외형만 담당한다.

| 모드 | 조건 | 구조 |
|---|---|---|
| 컴팩트 | 기본 | 1열 세로 스택. 폰은 화면 밀착(테두리·모서리 제거) |
| 태블릿 | 601–899px | 1열 + 셸 폭 상한 780px |
| **와이드** | `min-width:900px` **and** `min-aspect-ratio:5/4`, 또는 가로 폰 | **CSS Grid 2열** — 좌측 무대 전면, 우측 사이드바 |

와이드 모드는 `grid-template-areas` 로만 재배치하므로 **DOM 변경이 없다.**
가로비 조건(`5/4`)이 없으면 세로형 태블릿(1024×1366)이 2열로 잡혀 무대가 세로로 길쭉해지며
배율이 오히려 떨어진다(2.00 → 1.41). 이 조건은 장식이 아니다.

- `.office-room` 은 남는 공간을 그대로 채우는 무대 상자다. 픽셀 하한이 없다.
  476:337 과 어긋나는 만큼은 레이어가 레터박스로 흡수하고, 방 격자(`background-size`)는
  `--office-scale` 을 따라 함께 커진다.
- `--frame-h` / `--list-max` 실측 루프(`_syncFrameHeight` / `_syncListMax`)는 즉시 `return` 으로
  비활성화했다. 폭↔높이 순환참조를 CSS 로 제거했으므로 불필요하고, 매 리사이즈마다
  강제 리플로우만 유발한다. **되살리지 말 것.**
- `dvh` + `visualViewport` 대응(모바일 주소창), safe-area 패딩, 44px 터치 타깃,
  `overscroll-behavior:none`(드래그 중 당겨서 새로고침 방지) 추가.

### 2.3 아이콘 2단 에셋

무대를 키운 결과 128px 아이콘이 한계에 부딪혔다. 리팩터링 전에도 레티나 기준 이미 1.94× 확대
상태였고, 배율 2.74에서는 5.3× 확대가 된다. 원본 일러스트가 1024~1983px 이라 재생성했다.

| 경로 | 크기 | 용도 | 총량 |
|---|---|---|---|
| `itemImages/item_<n>.png` | 512px | 무대 (배율 최대 4.0×) | 501KB |
| `itemImages/thumb/item_<n>.png` | 128px | 목록·세트 카드 (20~26px) | 89KB |

단일 512px 로 통일하지 않은 이유: 목록 카드에 512px 을 물리면
25장 × 512×512×4B = **약 26MB 를 디코딩 메모리로 낭비**한다(모바일에서 특히 치명적).

`CYANOTYPE.item(id, size, hires)` 의 세 번째 인자로 분기한다. **배치구역 호출부 한 곳만 `hires=true`**,
나머지 3개 호출부는 썸네일 + `loading="lazy"`.

### 2.4 모바일 세로 예산

고정 UI 가 세로의 39~50% 를 먹고 있었다. **표시 항목은 하나도 지우지 않고 배치만 바꿨다.**

- 연봉협상 게이지 위에 버튼을 쌓던 것을 한 줄로 (−23px)
- `.header-left` flex-basis 200 → 150px (360px 화면에서 좌/우 블록이 한 줄에 들어감)
- 헤더 제목·행간 압축

| | 헤더 | 고정UI 점유율 | 무대 | 목록 |
|---|---|---|---|---|
| 390×844 전 → 후 | 172 → **98** | 39% → **26%** | 248 → **266** | 265 → **351** |
| 360×640 전 → 후 | 167 → **96** | 50% → **34%** | 196 → **224** | 120 → **192** |

### 2.5 기존 파이프라인 버그 2건 수정

`scripts/process_item_images.py` 를 실행하다 드러난 것으로, 반응형과 무관한 선행 버그다.

- **CRLF 파괴**: `update_index_html()` 이 `newline=''` 없이 텍스트 모드로 읽고 써서,
  실행할 때마다 `index.html` 4,362줄 전체가 CRLF → LF 로 바뀐다. diff 가 통째로 오염된다.
- **범위 폭주**: `itemImages/` 스캔 시 새로 만든 `thumb/` 하위폴더까지 훑어 목록이 오염된다.

두 번째와 별개로, `assets/items/` 에는 있으나 미가공이던 원본 10개가 파이프라인 실행으로
자동 등록되어 `ITEM_IMAGE_IDS` 가 25 → 35개로 늘어났다. 반응형과 무관한 게임 콘텐츠 변경이라
**25개로 되돌렸다.** 해당 10개는 아래와 같고, 노출하려면 파이프라인을 다시 돌리면 된다.

```
item_8, item_9, item_11, item_12, item_14, item_15, item_19, item_46, item_47, item_48
```

## 4. 튜닝 손잡이

`index.html` 의 `:root` 5개 변수로 조정한다.

| 변수 | 현재값 | 의미 |
|---|---|---|
| `--list-ideal` | 456px | 하단 목록이 확보하려는 높이 (모바일 400 / 짧은 화면 320) |
| `--list-min` | 132px | 목록 절대 최소 높이 |
| `--office-min-h` | 120px | 무대 최소 높이 |
| `--side-w` | `clamp(300px, 25vw, 480px)` | 와이드 모드 사이드바 폭 |
| `--shell-max-w` | 2400px | 셸 최대 폭 |

`--shell-max-w` 는 임의값이 아니라 **아이콘 해상도에서 역산한 값**이다
(디자인 최대 124px × 배율 4.13 = 512px). 더 키우려면 아이콘부터 재생성해야 한다.

### 알려진 한계

**4K DPR1(3840px)·울트라와이드(3440px)에서 30~38% 여백이 남는다.**
`--shell-max-w: 2400px` 상한 때문이고, 더 키우면 아이콘이 확대 흐림에 들어간다.
4K는 보통 DPR 2로 동작해 CSS 1920px 으로 잡히므로 실사용에서는 거의 걸리지 않는다.
이 구간까지 채우려면 `scripts/process_item_images.py` 의 `ICON_SIZE` 를 1024로 올려
재생성하면 된다(총량 501KB → 약 2.4MB).
