# _리팩터링전/ — 반응형 리팩터링 직전 상태

2026-09-10 반응형 리팩터링에서 **내용이 바뀐 파일 30개의 직전 원본**이다.
경로 구조는 프로젝트 루트 기준 그대로라, 이 폴더를 루트에 덮어쓰면
리팩터링 직전 상태로 정확히 되돌아간다.

## 되돌리기

```bash
# 프로젝트 루트에서
cp -a _리팩터링전/. .            # RESTORE.md, restore.sh, CHANGES.tsv 도 같이 복사되니 지워도 된다
rm -rf itemImages/thumb          # 리팩터링에서 새로 생긴 폴더(25개)
```

또는 동봉된 스크립트:

```bash
bash _리팩터링전/restore.sh
```

## 왜 여기에 30개만 있는가

원본 업로드본과 현재 트리를 파일별 SHA-256 으로 전수 대조한 결과다.

| 구분 | 개수 | 비고 |
|---|---|---|
| 동일 | 43 | 손대지 않음 |
| 변경 | 30 | **이 폴더에 직전 원본 보관** |
| 추가 | 25 | `itemImages/thumb/*.png` — 되돌릴 때는 폴더째 삭제 |
| 삭제 | 0 | 지운 파일 없음 |

`assets/items/` 35개(41MB)와 `추가파일/` 7개(2.5MB)는 **바이트 단위로 무변경**임을
해시로 확인했다. 동일한 41MB 를 한 벌 더 복제하는 대신 대조표만 남겼다.
파일별 이전/현재 해시와 크기는 `CHANGES.tsv` 에 전부 들어있다.

검증:

```bash
# 현재 파일이 CHANGES.tsv 의 '현재_SHA256' 과 일치하는지 확인
awk -F'\t' 'NR>1 {print $5"  "$2}' _리팩터링전/CHANGES.tsv | sha256sum -c -
```
